# Internationalisation (i18n)

Winkly ships in 26 languages. English (`apps/mobile/lib/i18n/locales/en.json`) is the source of truth; every other locale has the same flat keys (`keySeparator: false`, e.g. `"surprise.cta"`). There is **no runtime fallback to English** (`fallbackLng: false`), so a key must exist in every locale file.

## Adding text

1. Add the English string to `en.json` with a namespaced key (`screen.thing`).
   - Interpolate, never concatenate: `"weeklySpark.radiusKm": "{{km}} km"` → `t("weeklySpark.radiusKm", { km })`.
   - Counts use plurals: `"chat.members_one": "{{count}} member"`, `"chat.members_other": "{{count}} members"` → `t("chat.members", { count })`.
2. Use it: `const { t } = useTranslation();` then `<Text>{t("screen.thing")}</Text>`.
3. `npm run sync-i18n` — adds the key to every locale (a patch translation from `lib/i18n/patches/*.json` if one exists, otherwise the English text as a placeholder) and records each placeholder in `lib/i18n/translation-status.json`. (`translate-i18n` runs this sync itself.)
4. Translate: `npm run translate-i18n` (see [Machine translation](#machine-translation) below). A hand-made translation still works: a patch file in `lib/i18n/patches/` (`{ "<locale>": { "<key>": "…" } }`) + re-run sync, or edit the locale file directly.
5. `npm run audit-i18n` — must pass.

Never hard-code currency, units, date formats or time zones — use the locale formatters (prompt L4).

## The lint rule: no hard-coded text

`winkly/no-literal-string` (`apps/mobile/eslint-rules/no-literal-string.js`) flags, in `app/`, `components/`, `hooks/`, `providers/` and `lib/`:

- JSX text with a letter in it: `<Text>Hello</Text>`, `<Text>{ok ? "Yes" : "No"}</Text>`
- user-facing props: `title`, `subtitle`, `label`, `placeholder`, `accessibilityLabel`, `accessibilityHint`, `headerTitle`, `headerBackTitle`
- `Alert.alert` / `Alert.prompt` title, message and button `text`

Ignored: text without letters (emoji, `·`, numbers), brand names on the rule's allow list (`Winkly`, `OK`), `<Trans>` children, anything already going through a call like `t()`.

**How it's enforced**

| Where | Severity |
|---|---|
| `npm run lint` (whole app) | warn — the existing backlog doesn't block CI |
| `npm run lint:i18n-changed` (files changed vs. base) | **error** |

`scripts/lint-i18n-changed.mjs` diffs against the PR base (CI sets `I18N_LINT_BASE` to the PR base SHA, or the previous commit on a push; locally it defaults to `origin/main` and includes uncommitted and untracked files), sets `WINKLY_I18N_STRICT=1` (which `eslint.config.js` reads to flip the rule to `error`) and lints only those files. CI runs it in the **Lint** job, so a PR that touches a file must leave that file free of hard-coded text — including strings that were already there. That is deliberate: the backlog shrinks with every file we touch.

A genuinely non-translatable string (a debug-only screen, a proper noun) can be exempted in place with a reason:

```tsx
{/* eslint-disable-next-line winkly/no-literal-string -- dev-only screen */}
<Text>Debug</Text>
```

## Coverage audit

`npm run audit-i18n` reports:

1. **Key parity** — every locale has exactly `en.json`'s keys (fails otherwise).
2. **Real coverage per language** — a key counts as translated when its value differs from English and isn't a recorded placeholder, **or** it's allowlisted (no letters, a brand name / `OK`, or listed in `coverage-config.json`). A placeholder stays counted as untranslated even after the English changes, because `translation-status.json` stores a hash of the English it was copied from.
3. **Hard-coded strings left** — the count from the lint rule, with the worst files (skip with `-- --no-lint`, ~15 s).

```
  lang  tier  coverage          min
  uk    1      74% ███████···  453/612  74%
  de    1      49% █████·····  303/612  49%
  …
  fi    2      10% █·········   66/612  –
```

### Tiers and thresholds

Configured in `apps/mobile/lib/i18n/coverage-config.json`:

- **Tier 1** — `de, fr, es, it, pl, uk, nl, pt`: each has a `minCoverage` (%). The audit exits non-zero, and CI fails, if one drops below. Adding English keys without translating them for tier 1 lowers coverage, so translate new keys for tier 1 in the same PR.
- **Tier 2** — every other shipped language: reported, never blocks.

The minimums started at the coverage measured on 2026-09-22. **Raise them as translations land; never lower them** to get a PR through.

To allow a string that's legitimately identical to English, add the English value to `allowlist.values` (all languages), the key to `allowlist.keys`, or the key under `allowlist.locales.<code>` (one language, e.g. `de: ["auth.email"]` if "Email" were correct German).

## Machine translation

`npm run translate-i18n` (from the repo root or `apps/mobile`) fills every language and keeps it in sync with English:

```bash
npm run translate-i18n                         # all locales
npm run translate-i18n -- --locales de,fr      # a subset
npm run translate-i18n -- --dry-run            # what would be translated + character count, no API calls
npm run translate-i18n -- --check              # validate placeholders / plural forms / lengths only (--all shows warnings)
```

Per locale it first runs the same sync as `sync-i18n`, then translates:

- keys still holding an English placeholder (`needs_translation`),
- translations whose English changed since (their `en_hash` no longer matches `en.json`; the old translation is sent along as a hint),
- machine / legacy translations that break the glossary (a never-translate name or a keep-English word translated anyway — see below; human translations are only reported, never redone),
- every **CLDR plural form** the language needs, generated from English `_one` / `_other`: `pl`, `uk`, `ru`, `cs`, `sk`, `lt`, `hr` get `_few` / `_many`, `lv` `_zero`, `sl` `_two` / `_few`, `ga` and `mt` `_two` / `_few` / `_many` (from `Intl.PluralRules`, the same rules i18next uses). When English `_one` has no `{{count}}` ("One member") it is only used where "one" really means just 1 — Ukrainian "one" also covers 21, 31…, French covers 0, so those use `_other` and keep `{{count}}`.

Other options: `--only <key prefix>`, `--limit <n>` (per locale, for a trial run), `--force` (redo every machine/legacy translation, never human ones), `--provider`, `--concurrency`, `--batch`, `--no-cache`.

**Provider and keys.** Set one key in your shell or in `apps/mobile/.env.translate` (git-ignored by `.env.*` — never commit keys):

| Variable | Provider |
|---|---|
| `ANTHROPIC_API_KEY` | Claude (default when set). Model `claude-opus-5`; override with `WINKLY_TRANSLATE_MODEL`. Gets the full glossary, tone and plural instructions. |
| `DEEPL_API_KEY` | DeepL (`:fx` keys use the free API). Gets never-translate names and informal formality; no glossary notes. Plural forms are made by translating a real example number ("3 members" for Polish "few") and putting `{{count}}` back. DeepL may not support every language (e.g. Maltese); those fail and can be run with Claude. |

`--provider mock` makes fake `[de] …` translations for trying the pipeline without a key — don't commit its output.

Requests are batched (40 strings per Claude call, 50 per DeepL call, 4 / 2 in parallel) and every validated result is cached in `apps/mobile/.cache/translate-i18n/<locale>.json`, so an interrupted run resumes where it stopped and re-runs cost nothing. Locale files and the status file are written after each language.

**Validation.** Every translation is checked before it is written; a failing one is retried once with the reason, then left untranslated and the script exits 1:

- `{{placeholders}}` — none missing, none added, none renamed (fails)
- `<bold>` / `<terms>` / `<privacy>` tags for `<Trans>`, emoji, line breaks — kept (fails)
- names from `glossary.json` → `doNotTranslate` kept verbatim, and `keepEnglishInKeys` words kept in English in their keys (fails)
- keys under `button` / `chip(s)` / `tab(s)` (e.g. `deleteButton`, `form.chip.hike`, `allTab`) longer than **150 %** of the English → warning, and flagged in the review CSV

### Glossary

`apps/mobile/lib/i18n/glossary.json`:

- **`doNotTranslate`** — Winkly, Winkly AI, **Weekly Spark(s)** (a feature name, kept in English everywhere: "Dein Weekly Spark", "Твій Weekly Spark"), Super (tier), and the third-party brands. Checked exactly, in every key.
- **`keepEnglishInKeys`** — **Match** stays English in every language ("Deine Matches", "Twoje matche", "Твої Matches"; never "Treffer", "dopasowanie", "збіг", "матч"). Because English also uses "match" as a verb ("Passwords do not match") and for sports ("Watch a match"), this is enforced only in the listed keys (dating noun and the Match AI / Match Agent / AI Match Bridge names): the translation must contain "match" in Latin letters, any case, local endings allowed. **When you add a key that uses match in the dating sense, add it to this list.** For new keys not on the list the rule still reaches Claude through `terms.match`.
- **`terms`** — preferred translation per language for plan, planner, match (always "Match"), event, Premium (the tier; stays "Premium").
- **`tone`** — friendly, warm, casual; the user is addressed informally: du, tu, tú, ty, ти, ты, je, sinä, te, …
- **`version`** — bump it after changing the glossary so cached translations are redone (`--force` to retranslate existing ones).

`--check --all` lists existing translations that break it; machine and legacy ones are redone by the next `translate-i18n` run, human ones must be fixed through the review CSV (the export flags them in `note`). Values that are the same in every language ("Weekly Sparks", "Match", "Matches", "Match AI", "Match Agent") are on the coverage allowlist.

### Status and review

`translation-status.json` has one entry per locale and key:

| Entry | Meaning |
|---|---|
| `{"status": "needs_translation", "en_hash"}` | English placeholder |
| `{"status": "translated", "method": "machine", "reviewed": false, "date", "en_hash"}` | machine translation, not checked yet |
| `{"status": "translated", "method": "human", "reviewed": true, "date", "en_hash"}` | corrected by a native speaker |
| `{"status": "translated", "method": "legacy", "reviewed": false, "en_hash"}` | translation that predates the pipeline (origin unknown; treat like machine) |

`en_hash` is the English it was translated from; `same_as_en: true` marks a translation that is correctly identical to English ("Premium"). `npm run audit-i18n` prints how many translations are stale, machine, legacy and reviewed.

**Review workflow (one language):**

1. `npm run translate-i18n -- --export-review de` → `apps/mobile/i18n-review/de.csv` (git-ignored) with every translation not yet reviewed (`--all` for every key). Columns: `key, english, translation, method, reviewed, note, approve, correction, comment`. `note` flags untranslated, stale and too-long rows.
2. Send it to a native speaker (opens in Excel / Numbers / Google Sheets). For each row: `x` in **approve** if it's fine, or the better text in **correction** (keep the `{{placeholders}}`). Leave rows they didn't look at empty.
3. `npm run translate-i18n -- --import-review path/to/de.csv` — corrections become `method: "human", reviewed: true`; approvals are marked `reviewed: true`. Corrections that break placeholders, and rows whose English changed since the export, are skipped and listed (exit 1). Commit the locale file and `translation-status.json`.

Human translations are never overwritten by `--force`. If the English of a human translation changes, the key is machine-translated again (with the human version as a hint) and shows up in the next review export.

## Files

| File | What |
|---|---|
| `lib/i18n.ts` | i18next setup, supported languages |
| `lib/i18n/locales/*.json` | translations (flat keys) |
| `lib/i18n/patches/*.json` | per-feature translations merged in by `sync-i18n` |
| `lib/i18n/translation-status.json` | generated — per locale and key: placeholder, or translation with method / reviewed / date / en_hash (see above) |
| `lib/i18n/glossary.json` | never-translate names, preferred terms, tone per language |
| `lib/i18n/coverage-config.json` | tiers, tier-1 minimums, allowlist |
| `scripts/sync-i18n-keys.mjs`, `scripts/audit-i18n.mjs`, `scripts/lint-i18n-changed.mjs` | the tooling above (shared logic in `scripts/lib/i18nCoverage.js`, file I/O in `scripts/lib/i18nFiles.mjs`) |
| `scripts/translate-i18n.mjs` | machine translation, validation, review export/import (`scripts/lib/i18nTranslate.js`, providers in `scripts/lib/translationProviders.mjs`) |
| `eslint-rules/no-literal-string.js` | the lint rule |
