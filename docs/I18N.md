# Internationalisation (i18n)

Winkly ships in 26 languages. English (`apps/mobile/lib/i18n/locales/en.json`) is the source of truth; every other locale has the same flat keys (`keySeparator: false`, e.g. `"surprise.cta"`). There is **no runtime fallback to English** (`fallbackLng: false`), so a key must exist in every locale file.

## Adding text

1. Add the English string to `en.json` with a namespaced key (`screen.thing`).
   - Interpolate, never concatenate: `"weeklySpark.radiusKm": "{{km}} km"` → `t("weeklySpark.radiusKm", { km })`.
   - Counts use plurals: `"chat.members_one": "{{count}} member"`, `"chat.members_other": "{{count}} members"` → `t("chat.members", { count })`.
2. Use it: `const { t } = useTranslation();` then `<Text>{t("screen.thing")}</Text>`.
3. `npm run sync-i18n` — adds the key to every locale (a patch translation from `lib/i18n/patches/*.json` if one exists, otherwise the English text as a placeholder) and records each placeholder in `lib/i18n/translation-status.json`.
4. Translate: `npm run translate-i18n` (see below), or hand-write a patch file in `lib/i18n/patches/` (`{ "<locale>": { "<key>": "…" } }`) and re-run sync. Tier-1 languages must be translated in the same PR (the audit fails otherwise).
5. `npm run audit-i18n` — must pass.

Never hard-code currency, units, date formats or time zones — use the locale formatters (prompt L4).

## Machine translation: `npm run translate-i18n`

`scripts/translate-i18n.mjs` asks Claude to translate every English placeholder recorded in `translation-status.json`, plus any plural forms a language needs that the file lacks (`_few`/`_many` for pl, uk, cs…), then re-runs `sync-i18n`.

```bash
npm run translate-i18n -- --dry-run            # counts per language, no API calls
npm run translate-i18n -- --locales fi --limit 50   # small trial, then review the diff
npm run translate-i18n                          # everything
```

- Credentials: `ANTHROPIC_API_KEY` (or an `ant auth login` profile). Model `claude-opus-5`; override with `--model` / `TRANSLATE_I18N_MODEL`.
- Each reply is checked: a translation that drops or adds a `{{placeholder}}` or tag is discarded and listed; it stays English and is retried next run.
- The locale file is written after every batch, so an interrupted run keeps its progress.
- Existing real translations are sent as style examples so tone (du/Sie, tu/vous) stays consistent. Still spot-check each language before merging.

## The lint rule: no hard-coded text

`winkly/no-literal-string` (`apps/mobile/eslint-rules/no-literal-string.js`) flags, in `app/`, `components/`, `hooks/`, `providers/` and `lib/`:

- JSX text with a letter in it: `<Text>Hello</Text>`, `<Text>{ok ? "Yes" : "No"}</Text>`
- user-facing props: `title`, `subtitle`, `label`, `placeholder`, `accessibilityLabel`, `accessibilityHint`, `headerTitle`, `headerBackTitle`
- `Alert.alert` / `Alert.prompt` title, message and button `text`

Ignored: text without letters (emoji, `·`, numbers), brand names on the rule's allow list (`Winkly`, `OK`), `<Trans>` children, anything already going through a call like `t()`.

**How it's enforced**

| Where | Severity |
|---|---|
| `npm run lint` (whole app) | warn — the existing backlog doesn't block CI |
| `npm run lint:i18n-changed` (files changed vs. base) | **error** |

`scripts/lint-i18n-changed.mjs` diffs against the PR base (CI sets `I18N_LINT_BASE` to the PR base SHA, or the previous commit on a push; locally it defaults to `origin/main` and includes uncommitted and untracked files), sets `WINKLY_I18N_STRICT=1` (which `eslint.config.js` reads to flip the rule to `error`) and lints only those files. CI runs it in the **Lint** job, so a PR that touches a file must leave that file free of hard-coded text — including strings that were already there. That is deliberate: the backlog shrinks with every file we touch.

A genuinely non-translatable string (a debug-only screen, a proper noun) can be exempted in place with a reason:

```tsx
{/* eslint-disable-next-line winkly/no-literal-string -- dev-only screen */}
<Text>Debug</Text>
```

## Coverage audit

`npm run audit-i18n` reports:

1. **Key parity** — every locale has exactly `en.json`'s keys (fails otherwise).
2. **Real coverage per language** — a key counts as translated when its value differs from English and isn't a recorded placeholder, **or** it's allowlisted (no letters, a brand name / `OK`, or listed in `coverage-config.json`). A placeholder stays counted as untranslated even after the English changes, because `translation-status.json` stores a hash of the English it was copied from.
3. **Hard-coded strings left** — the count from the lint rule, with the worst files (skip with `-- --no-lint`, ~15 s).

```
  lang  tier  coverage          min
  uk    1      74% ███████···  453/612  74%
  de    1      49% █████·····  303/612  49%
  …
  fi    2      10% █·········   66/612  –
```

### Tiers and thresholds

Configured in `apps/mobile/lib/i18n/coverage-config.json`:

- **Tier 1** — `de, fr, es, it, pl, uk, nl, pt`: each has a `minCoverage` (%). The audit exits non-zero, and CI fails, if one drops below. Adding English keys without translating them for tier 1 lowers coverage, so translate new keys for tier 1 in the same PR.
- **Tier 2** — every other shipped language: reported, never blocks.

The minimums started at the coverage measured on 2026-09-22. **Raise them as translations land; never lower them** to get a PR through.

To allow a string that's legitimately identical to English, add the English value to `allowlist.values` (all languages), the key to `allowlist.keys`, or the key under `allowlist.locales.<code>` (one language, e.g. `de: ["auth.email"]` if "Email" were correct German).

## Files

| File | What |
|---|---|
| `lib/i18n.ts` | i18next setup, supported languages |
| `lib/i18n/locales/*.json` | translations (flat keys) |
| `lib/i18n/patches/*.json` | per-feature translations merged in by `sync-i18n` |
| `lib/i18n/translation-status.json` | generated — English placeholders still to translate (`locale → key → { status, en_hash }`) |
| `lib/i18n/coverage-config.json` | tiers, tier-1 minimums, allowlist |
| `scripts/sync-i18n-keys.mjs`, `scripts/audit-i18n.mjs`, `scripts/lint-i18n-changed.mjs`, `scripts/translate-i18n.mjs` | the tooling above (shared logic in `scripts/lib/i18nCoverage.js`) |
| `eslint-rules/no-literal-string.js` | the lint rule |
